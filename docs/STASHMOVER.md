# FO 自动搬运（StashMover）配置指南

> 代码：`fo/src/main/java/com/fo/addon/modules/StashMover.java`（约 5.3k 行，69 项设置）
> 纯逻辑：`utils/StashMoveLogic`、`StashPearlLogic`、`PeerMessageLogic`、`StashChestSpotLogic`、`StashStats`
> 历史修复记录见 [`CHANGELOG.md`](CHANGELOG.md)。

## 三种模式

| 模式 | 用途 |
| --- | --- |
| 搬运端（双号） | 1 号在待搬运箱区取货 → 发「拉我N」→ 被拉到存储区 → 卸货 → 投回程珍珠 → 自杀回重生点，循环 |
| 拉珍珠端（双号） | 2 号收到「拉我N」后点活板门，把 1 号拉过珍珠超穿通道 |
| 三号模式 | 1 号搬运端 / 2 号待搬运箱端 / 3 号存储箱端；三个号各开一个，1 号不自杀 |

## 场地硬性前提

- **双号模式**：1 号重生点必须在待搬运箱旁边（箱子搜索半径最大 20 格，超出会持续报警）。
- **珍珠超穿通道**：活板门正下方 1 格必须是水；活板门上方 1~3 格有告示牌（投掷侧的第一优先级来源）。
- **珍珠箱/存储箱/待搬运箱**：建议使用双箱，模块会自动识别另一半并成对保护。
- **末影箱**：可选，放在两区附近可单趟多搬 27 个潜影盒；也可以在设置里直接填坐标。

## 关键设置

- **待搬运方式**：自动搜索 / 单箱子 / 区域框选。
- **双号/三号角色**：按账号选择，三个号互斥。
- **私信协议**：`/m` 或 `/tell`，关键字「拉我N」「收到N」；双号拉珍珠端必须填白名单。
- **自杀延时**：默认 1200 tick；设 0 = 确认后立刻死，会掉珍珠。
- **只拿潜影盒**：开启后只搬潜影盒；`NO_MATCH` 不会拉黑箱子。
- **1 tick 瞬时存取**：测试开关，默认关；只改点击节奏，不改状态机。
- **赶路不挖掘**：默认开，避免 Baritone 为了到 XZ 一路挖穿地形。

## 常见问题定位

| 现象 | 优先检查 |
| --- | --- |
| 点了箱子没反应 | 开箱距离（默认 2.0，按「眼睛→箱体」算）、落脚点是否被挡、是否连续点不开触发了换格 |
| 站不到活板门正前方 | 告示牌朝向、活板门 FACING、门板碰撞箱；模块只在正前方投掷 |
| 投了珍珠但没被拉走 | 珍珠是否进气泡柱、拉珍珠端白名单/冷却、私信关键字与 N 是否匹配 |
| 被拉到存储区后不卸货 | 存储箱坐标/末影箱坐标、双箱搭档、是否被「只拿潜影盒」过滤 |
| 存储箱满后卡住 | 漏斗是否在吸物品；p35 起会等 3 分钟再报错 |
| 走到箱子正上方/向下挖 | 使用 p25+ 的 `StashChestSpotLogic` 落脚点；不要用旧的 GoalXZ 目标 |
| 卡脚/位置反复被拉回 | `TeleportFloodDetector` 是否触发；检查是否有方块/水柱顶住 |

## 安全与隐私

- 模块日志默认不输出绝对坐标（`NoCoordinatesInLogsTest` 防回归）。
- `/suicide --confirm` 是默认下线方式；不确认服务器死亡不掉落时请改用其它方式。
- 公开仓库/录屏前请检查设置里的服务器名、私信白名单、珍珠点映射表。

## 测试

- 纯逻辑单测覆盖：私信解析/配对、珍珠补货、双箱配对、统计、落点选择、投掷判定等。
- 完整双号/三号流程需要两个/三个账号和真实场地，当前未纳入自动 CI。
